# Ласточкин хвост

**Ласточкин хвост** — дайджест столярного ремесла, деревообработки и работы с деревом.
Сайт работает как куратор: собирает свежие материалы из сообществ мастеров, отсеивает рекламу и
малозначимое, раскладывает по рубрикам и публикует в структурированном виде.

Аудитория — русскоязычные столяры, redwood-мейкеры, любители и профессионалы, которым нужны
практические идеи, обзоры инструмента и техники работы. Тон — уважительный к ремеслу, без снобизма,
с акцентом на «сделай сам» и проверенные методы.

---

## Быстрый старт

```bash
npm install        # установка зависимостей
npm run dev        # режим разработки (http://localhost:4321)
npm run build      # сборка в dist/
npm run preview    # предпросмотр собранного сайта
npm run collect    # сбор материалов из источников
npm run backfill   # перевод уже собранных материалов на русский
```

Сайт статический: на выходе — готовые HTML-файлы в `dist/`, которые кладутся на любой хостинг.

## Как это работает

```text
Источники        →  Сбор        →  Нормализация  →  Перевод   →  Фильтрация
(Telegram, RSS,     scripts/        scripts/         scripts/      scripts/
 YouTube)            collect.ts      normalize.ts     ai/          filter.ts
                                                     translate.ts     │
                                                                      │
                        Публикация ←  AI-резюме  ←  Категоризация     │
                        data/           scripts/ai/      scripts/       │
                        materials.json  summarize.ts     categorize.ts
```

1. **Сбор.** Адаптеры в `scripts/adapters/` тянут сырые записи из включённых источников.
   Каждый источник изолирован: сбой одного не ломает остальные.
2. **Нормализация.** `scripts/normalize.ts` чистит HTML, выравнивает даты, определяет тип контента.
3. **Перевод.** `scripts/ai/translate.ts` переводит иноязычные заголовки и описания на русский.
   Без API-ключа перевод пропускается — материал остаётся на языке источника.
4. **Фильтрация.** `scripts/filter.ts` отсеивает рекламу и материалы без практической ценности
   по спискам маркеров (русский и английский).
5. **Категоризация.** `scripts/categorize.ts` относит материал к рубрике и вытащивает теги.
6. **Резюме.** `scripts/ai/summarize.ts` генерирует 1–2 предложения на русском через LLM.
   Без API-ключа используется эвристический fallback — сбор никогда не падает.
7. **Публикация.** Результат пишется в `data/materials.json`, откуда его читают страницы.

## Рубрики

| Рубрика | Слаг | О чём |
| --- | --- | --- |
| Инструмент | `instrument` | Обзоры, сравнения, выбор инструмента под задачу |
| Проект/чертёж | `project` | Чертежи, разборы изготовления, расчёты |
| Техника и приёмы | `technique` | Рабочие способы, которые экономят время |
| Безопасность | `safety` | Охрана труда, пыль, ЛКМ, средства защиты |
| События/выставки | `events` | Встречи, мастер-классы, выставки |
| Вдохновение | `inspiration` | Работы мастеров и идеи для своих проектов |

Слаг рубрики используется в ссылке `/archive/?category=<slug>` и в имени файла обложки
`public/images/categories/<slug>.webp`.

## Страницы

- **Главная** (`/`) — hero-блок с метриками дайджеста, плитки рубрик и свежий выпуск
- **Архив** (`/archive/`) — все материалы с чипами-фильтрами по рубрике, источнику и типу, поиском
  и лентой по месяцам
- **Материал** (`/<slug>/`) — обложка рубрики, заголовок, мета-строка, прогресс-бар чтения,
  резюме, теги и ссылка на первоисточник

## Визуальный слой

- Палитра «тёплое дерево + современный акцент» задана в `src/styles/global.css`
  в блоке `@theme`: графит, песочный, терракота, янтарь, тил, слива, охра.
- Повторяемые блоки описаны как `@utility` Tailwind v4: `card`, `card-lift`, `chip`,
  `chip-active`, `badge`, `tag`, `btn` и производные.
- Обложки рубрик — собственная векторная графика в формате WebP
  (`public/images/categories/`), лицензия не требуется.
- Рубрики, их цвета и иконки описаны в `src/lib/categories.ts`, выбор обложки —
  в `src/lib/covers.ts`.

## Настройка

- `src/config/sources.json` — список источников (Telegram, RSS, YouTube)
- `src/config/site.json` — название, подзаголовок, описание, ссылка на сообщество в ВК
- `src/config/ai.json` — параметры LLM для генерации резюме и перевода материалов
- `.env` — ключи API (никогда не коммитится, шаблон в `.env.example`)

### Бренд

Название и подзаголовок живут в одном месте — `src/config/site.json`:

```json
{
  "name": "Ласточкин хвост",
  "tagline": "дайджест столярного ремесла",
  "title": "Ласточкин хвост — дайджест столярного ремесла",
  "description": "...",
  "vkUrl": "https://vk.com/your_community_link"
}
```

Компоненты не содержат литералов: всё подтягивается через хелперы `src/lib/site.ts`
(`getSiteName()`, `getTagline()`, `formatTitle()`), а те отдают значения в шапку, подвал, hero,
`<title>`, `og:title`, `og:site_name` и `application-name`. Переименование дайджеста — это правка
одной строки в `src/config/site.json`, а не поиск по репозиторию.

Подробная инструкция по добавлению источников, подключению MCP и деплою — в [AGENTS.md](AGENTS.md).

### Перевод материалов

Иноязычные материалы (английский и другие языки) переводятся на русский **на этапе сбора**:
посетитель получает уже готовый русский текст, из браузера запросы к LLM не уходят.

Перевод выполняет `scripts/ai/translate.ts`, шаг стоит между нормализацией и фильтрацией —
фильтр получает шанс отсеять мусор по русским маркерам уже переведённого текста. Модель и промпт
задаются только в `src/config/ai.json`:

```json
{
  "translation": {
    "enabled": true,
    "model": "google/gemini-flash-latest",
    "maxTokens": 1024,
    "temperature": 0.2,
    "timeoutMs": 20000,
    "prompt": "Переведи текст ... \"{text}\""
  }
}
```

- **Ключ API** — `OPENROUTER_API_KEY` или `LLM_API_KEY` в `.env`. Без ключа перевод пропускается
  с предупреждением, конвейер не падает.
- **Кэш** — `scripts/cache/translations.json`, коммитится в репозиторий. Ключ записи — SHA-256 от
  `текст + "→ru" + модель`, значение — `{ text, model, createdAt }`. Повторный сбор не платит
  за уже переведённое, смена модели даёт новые ключи. Файл создаётся сам, повреждённый не роняет сбор.
- **Как отключить** — `"translation": { "enabled": false }` в `src/config/ai.json`.
- **Если перевести не удалось** (таймаут, ошибка API, пустой ответ) — материал публикуется
  на языке источника с бейджем «Оригинал». Успешно переведённые получают бейдж «Переведено».

Язык текста определяет простая эвристика в `src/lib/language.ts`: доля кириллицы больше 0.6 —
русский, иначе иноязычный. Короткие строки (короче 20 символов) переводятся без оглядки на
эвристику, а русские длинные тексты не отправляются в API вовсе.

#### Докач уже собранных материалов

Шаг перевода появился в конвейере не сразу, поэтому часть материалов в `data/materials.json`
осталась на языке источника. Докачать их помогает `scripts/backfill-translations.ts`:

```bash
npm run backfill                    # перевести все материалы
npm run backfill -- --dry-run       # показать изменения, не записывая data/materials.json
npm run backfill -- --only <id>     # перевести только указанный материал
npm run backfill -- --recategorize  # дополнительно пересчитать рубрику и теги
```

Что делает докач:

- переводит `title` и `description`, а `summary` перегенерирует заново — так же, как при обычном сборе;
- **не меняет** `id`, `url`, `publishedAt`, `collectedAt` — адреса страниц и ссылки на источники остаются прежними;
- проставляет `translated` и `sourceLang`, поэтому в интерфейсе появляется бейдж «Переведено»;
- русские материалы пропускает, неудачные переводы оставляет на языке источника (бейдж «Оригинал»);
- требует ключ API: без `OPENROUTER_API_KEY` / `LLM_API_KEY` в `.env` скрипт ничего не меняет;
- кладёт переводы в общий кэш `scripts/cache/translations.json`, поэтому повторный запуск не платит дважды.

Запускать нужно с ключом в `.env`. Результат (`data/materials.json` и кэш переводов) коммитится в репозиторий.

## Деплой

Публикация на GitHub Pages настроена через `.github/workflows/deploy.yml`:
после пуша в `main` сайт собирается и выкладывается автоматически.

В `Settings → Pages → Build and deployment` выберите **GitHub Actions**.

## Структура

```text
.
├── .github/workflows/   # ci.yml (линты + сборка), deploy.yml (GitHub Pages)
├── data/materials.json  # собранные и обработанные материалы
├── public/              # favicon.svg, images/categories/*.webp, og-default.webp

│   ├── adapters/        # telegram.ts, rss.ts, youtube.ts
│   ├── ai/summarize.ts  # LLM-резюме + fallback
│   ├── ai/translate.ts  # перевод иноязычных материалов на русский
│   ├── backfill-translations.ts # докач переводов для уже собранных материалов
│   ├── cache/           # translations.json — кэш переводов (коммитится)
│   ├── collect.ts       # точка входа
│   ├── categorize.ts    # рубрикация и теги
│   ├── filter.ts        # фильтрация рекламы и шума
│   └── normalize.ts     # нормализация полей
├── src/
│   ├── components/      # карточки, теги, фильтры, шапка, подвал, StatsBand, CategoryGrid
│   ├── config/          # sources.json, ai.json, site.json
│   ├── layouts/         # BaseLayout.astro
│   ├── lib/             # типы, утилиты, язык, данные, рубрики, обложки, брендинг
│   ├── pages/           # index, archive, [slug]
│   └── styles/          # global.css (тема Tailwind v4)
├── AGENTS.md
└── astro.config.mjs
```
