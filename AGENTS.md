# AGENTS.md — Ласточкин хвост

Документ описывает, как настроить, запустить и расширить сайт-дайджест по столярному ремеслу,
деревообработке и работе с деревом.

## 1. Технический стек

- **[Astro](https://astro.build/)** — статический сайт (static-first), минимальный JS
- **[Tailwind CSS](https://tailwindcss.com/)** — стилизация (v4, CSS-first: тема в `src/styles/global.css`)
- **TypeScript** — типизация
- **Node.js 22+** — для сборки и скриптов (проверено на 24)
- **GitHub Pages** — хостинг

## 2. Установка и запуск

```bash
# Установка зависимостей
npm install

# Режим разработки
npm run dev

# Сборка
npm run build

# Предпросмотр собранного сайта
npm run preview

# Сбор материалов из источников
npm run collect

# Докач переводов для уже собранных материалов
npm run backfill
```

## 4. Визуальный слой

### 4.1. Палитра

Направление — «тёплое дерево + современный акцент». Все цвета заданы только в
`src/styles/global.css` в блоке `@theme`; в компонентах используются классы
(`bg-terracotta-600`), inline-значений нет.

| Группа | Переменные | Роль |
| --- | --- | --- |
| Поверхности | `--color-paper`, `--color-paper-100`, `--color-paper-200` | Фон страницы и секций |
| Графит | `--color-graphite-900 … 300` | Текст, тёмные плашки |
| Песочный | `--color-sand-50 … 300` | Карточки, границы, вторичные заливки |
| Терракота | `--color-terracotta-100 … 700` | Основной акцент, рубрика «Инструмент» |
| Янтарь | `--color-amber-100 … 700` | Второй акцент, рубрика «Проект/чертёж» |
| Тил | `--color-teal-100 … 700` | Акцент второго порядка, рубрика «Техника и приёмы» |
| Слива | `--color-plum-100 … 700` | Рубрика «События/выставки» |
| Охра | `--color-ochre-100 … 700` | Рубрика «Вдохновение» |
| ВК | `--color-vk`, `--color-vk-dark` | Фирменный синий кнопок |

Правила доступности:

- основной текст — `--color-graphite-900` на `--color-paper` (контраст ≈ 15:1);
- вторичный текст — `--color-graphite-500` (≈ 5.8:1, AA);
- белый текст допустим только на оттенках `-600` и темнее (≥ 5.7:1);
- янтарь используется как заливка с графитовым текстом (≈ 8.4:1), не белым.

Форма задаётся в той же теме: `--radius-card` (16 px), `--radius-chip` (8 px),
`--shadow-card`, `--shadow-lift`. Повторяемые блоки описаны как `@utility`:
`card`, `card-lift`, `chip`, `chip-muted`, `chip-active`, `chips-scroll`, `badge`,
`tag`, `btn`, `btn-primary`, `btn-vk`, `btn-ghost`.

> В Tailwind v4 файл `tailwind.config.mjs` отсутствует, `@apply` по обычным классам
> не резолвится — повторяемые стили добавляются только через `@utility`.

### 4.2. Рубрики

Справочник рубрик лежит в `src/lib/categories.ts`: слаг, короткая подсказка, готовые
классы Tailwind (`badge`, `accent`, `soft`, `gradient`) и SVG-иконка в сетке 24×24.
Классы записаны литералами — так Tailwind видит их при сканировании.

### 4.3. Обложки

Обложка материала подбирается по рубрике: `public/images/categories/<slug>.webp`
(1600×900, формат 16:9). Если файла рубрики нет — используется `default.webp`.

Файлы лежат в репозитории и генерируются офлайн: векторная иллюстрация (текстура
дерева + мотив рубрики) растеризуется в WebP через `sharp` (уже в зависимостях
Astro, новых пакетов не нужно). Лицензия на изображения отсутствует — это
собственная векторная графика проекта.

Точка расширения — `src/lib/covers.ts`:

```ts
getCoverForMaterial(material) // обложка по рубрике
getCategoryCover(category)    // путь обложки рубрики
```

Если у материала появится поле `cover` со ссылкой на сгенерированное изображение,
`getCoverForMaterial()` вернёт его — код страниц менять не придётся. Само подключение
генерации (переменные `IMAGE_GEN_API_KEY` или `OPENROUTER_API_KEY`) не реализовано:
это отдельная задача владельца проекта. Доступ к ключам — только через `.env`,
в `.env.example` добавляются лишь имена переменных, без значений.

## 5. Конфигурация

### 5.1. Источники — `src/config/sources.json`

```json
{
  "telegram": [
    { "name": "@stolyarka_vmeste", "enabled": true, "notes": "..." }
  ],
  "rss": [
    { "name": "Example Blog", "url": "https://example.com/feed.xml", "enabled": false }
  ],
  "youtube": []
}
```

**Как добавить новый источник:**

1. Добавьте запись в соответствующий раздел (`telegram`, `rss`, `youtube`) с `enabled: true`
2. Для RSS обязательно укажите рабочий `url` (Atom/RSS)
3. Для Telegram — название канала без `https://t.me/` или с `@`
4. Запустите `npm run collect` для проверки

### 5.2. Настройки сайта — `src/config/site.json`

```json
{
  "name": "Ласточкин хвост",
  "tagline": "дайджест столярного ремесла",
  "title": "Ласточкин хвост — дайджест столярного ремесла",
  "description": "Кураторская подборка материалов по столярному ремеслу: ...",
  "vkUrl": "https://vk.com/your_community_link"
}
```

**Бренд живёт в `site.json`.** Это единственный источник названия и подзаголовка: компоненты
не содержат литералов, всё подтягивается через хелперы `src/lib/site.ts`:

| Хелпер | Что отдаёт |
| --- | --- |
| `getSiteName()` | Название бренда — wordmark в шапке, подзаголовок футера, H1 в hero, `og:site_name`, `application-name` |
| `getTagline()` | Подзаголовок бренда — строка под wordmark в шапке, подзаголовок hero, подпись в подвале |
| `formatTitle(pageTitle?)` | `<title>`: на главной — `title` из конфига, на внутренних — «Заголовок — Название» |

Чтобы переименовать дайджест, правьте `name` и `title` в `src/config/site.json` — код и
разметку трогать не нужно. Ссылка на ВК берётся отсюда же и отображается в шапке и подвале;
замените `vkUrl` на актуальную ссылку.

### 5.3. AI-резюме — `src/config/ai.json` и `.env`

Конфиг:

```json
{
  "enabled": true,
  "provider": "openrouter",
  "model": "google/gemini-2.5-flash-preview-05-20",
  "maxTokens": 256,
  "temperature": 0.4,
  "prompt": "..."
}
```

Переменные окружения (никогда не коммитить реальные ключи):

```env
OPENROUTER_API_KEY=sk-or-v1-...
# или
LLM_API_KEY=...
```

Файл `.env.example` содержит шаблон. При отсутствии ключа или ошибке AI автоматически используется
эвристическое резюме (fallback) — `npm run collect` не упадёт.

Провайдер выбирается полем `provider`:

- `openrouter` — `https://openrouter.ai/api/v1/chat/completions`
- `openai` — `https://api.openai.com/v1/chat/completions`

Оба API совместимы с форматом OpenAI, поэтому промпт и модель настраиваются одинаково.

### 5.4. Перевод материалов — `src/config/ai.json` и `scripts/ai/translate.ts`

Иноязычные материалы переводятся на русский **на этапе сбора** (build-time), а не в браузере:
посетитель получает уже готовый русский текст. Шаг перевода стоит между `normalize.ts` и
`filter.ts` — фильтр работает с русским текстом.

Конфиг — блок `translation` в том же `src/config/ai.json`:

```json
{
  "translation": {
    "enabled": true,
    "model": "google/gemini-flash-latest",
    "comment": "Модель перевода задаётся только здесь. Альтернативы: openai/gpt-luna-latest, ...",
    "maxTokens": 1024,
    "temperature": 0.2,
    "timeoutMs": 20000,
    "prompt": "Переведи текст ... \"{text}\""
  }
}
```

**Правила:**

- **Модель перевода задаётся только в `ai.json`, в коде не хардкодится.** Смена модели меняет
  ключи кэша — старые переводы не мешают.
- **Кэш коммитится в репозиторий** — `scripts/cache/translations.json`. Ключ записи — SHA-256 от
  `текст + "→ru" + модель`, значение — `{ text, model, createdAt }`. Файл создаётся сам;
  повреждённый — предупреждение и пустой кэш, сбор не падает.
- **При отсутствии ключа перевод пропускается без падения конвейера**: материал публикуется
  на языке источника, в лог уходит предупреждение.
- **Таймаут запроса** — `translation.timeoutMs` (по умолчанию 20000). Любая ошибка API, таймаут
  или пустой ответ оставляют оригинальный текст.
- **Короткие строки** (короче 20 символов) переводятся без оглядки на эвристику языка;
  длинные русские тексты в API не отправляются.
- **Язык** определяется эвристикой в `src/lib/language.ts` — общей для конвейера и интерфейса:
  доля кириллицы больше 0.6 — русский, иначе иноязычный.

В материале (`src/lib/types.ts`) после перевода появляются поля `translated` и `sourceLang`.
Интерфейс показывает бейдж «Переведено» (`TranslationBadge.astro`) или «Оригинал», если
перевода не случилось, а текст остался иноязычным.

#### Докач ранее собранных материалов — `scripts/backfill-translations.ts`

Материалы, собранные до появления шага перевода, остались на языке источника. Скрипт
докачивает их по месту:

```bash
npm run backfill                    # перевести все материалы
npm run backfill -- --dry-run       # показать изменения, не записывая data/materials.json
npm run backfill -- --only <id>     # перевести только указанный материал
npm run backfill -- --recategorize  # дополнительно пересчитать рубрику и теги
```

**Правила докача:**

- **Идентификаторы не меняются.** `id`, `url`, `publishedAt`, `collectedAt` остаются прежними —
  адреса страниц и ссылки на источники не ломаются.
- **Русские материалы пропускаются**, неудачные переводы остаются на языке источника.
- **Резюме перегенерируется** через `summarize()`, если текст удалось перевести, — так же,
  как при обычном сборе.
- **Ключ API обязателен:** без `OPENROUTER_API_KEY` / `LLM_API_KEY` скрипт ничего не меняет
  и завершается с кодом 1. Переводы попадают в общий кэш `scripts/cache/translations.json`.
- **`--dry-run` не трогает `data/materials.json`**, но запросы к API и запись в кэш переводов
  всё равно происходят.

## 6. MCP для Telegram/RSS

Для унифицированного сбора рекомендуется использовать MCP-серверы. Основной код не жёстко привязан
к конкретному MCP — адаптеры находятся в `scripts/adapters/` и легко заменяются.

### Рекомендуемый вариант

- [`@goldjee/news-digest-mcp`](https://www.npmjs.com/package/@goldjee/news-digest-mcp) — агрегатор
  новостных и RSS-источников. Конфигурируется через переменные окружения.

### Как подключить через opencode.json

Создайте или отредактируйте `opencode.json` в корне проекта:

```json
{
  "mcp": {
    "servers": {
      "news-digest": {
        "command": "npx",
        "args": ["-y", "@goldjee/news-digest-mcp"],
        "env": {
          "TELEGRAM_API_ID": "${TELEGRAM_API_ID}",
          "TELEGRAM_API_HASH": "${TELEGRAM_API_HASH}",
          "TELEGRAM_SESSION": "${TELEGRAM_SESSION}"
        }
      }
    }
  }
}
```

### Настройка Telegram

Если нужно прямое чтение закрытых каналов через Telegram Client API:

1. Получите `api_id` и `api_hash` на [my.telegram.org](https://my.telegram.org)
2. Сохраните их в `.env` (см. `.env.example`)
3. При первом запуске потребуется интерактивная авторизация — код из SMS или из приложения
4. **Никогда не коммитьте токены, сессии или ключи.** Используйте `.env`

Без `TELEGRAM_SESSION` скрипт читает публичную ленту `t.me/s/<канал>` — авторизация не нужна,
но доступны только открытые каналы.

### Альтернативы

- Любой RSS-агрегатор через `fetch` и `rss-parser`
- Собственный адаптер в `scripts/adapters/` — добавьте файл, реализуйте сборщик материалов
  и подключите его в `scripts/collect.ts`

**Принцип:** `src/lib/` и `src/pages/` не знают про MCP. Вся работа с внешними источниками
инкапсулирована в `scripts/`.

## 7. Деплой на GitHub Pages

В репозитории уже настроен workflow `.github/workflows/deploy.yml`.

**Порядок настройки:**

1. Перейдите в Settings → Pages → Build and deployment: выберите **GitHub Actions**
2. Закоммитьте и запушьте изменения в `main`
3. Workflow автоматически соберёт и задеплоит сайт
4. URL вида: `https://<username>.github.io/<repo-name>/`

В `astro.config.mjs` указаны `site` и `base`. При смене имени репозитория поправьте `base`.

## 8. Расширение проекта

### Добавить новый источник

См. раздел 5.1. Минимально — добавить в `sources.json` и при необходимости адаптер.

### Добавить новую рубрику

1. Добавьте значение в union `Category` в `src/lib/types.ts`
2. Добавьте ключевые слова в `scripts/categorize.ts`
3. Добавьте запись в `src/lib/categories.ts`: слаг, подсказка, цвета (`badge`, `accent`,
   `soft`, `gradient`) и SVG-иконка
4. Положите обложку в `public/images/categories/<slug>.webp`

### Изменить цвета и шрифты

Tailwind v4 настроен через CSS-first `@theme` в `src/styles/global.css`. Файла
`tailwind.config.mjs` нет: палитра (`--color-paper-*`, `--color-graphite-*`,
`--color-sand-*`, `--color-terracotta-*`, `--color-amber-*`, `--color-teal-*`,
`--color-plum-*`, `--color-ochre-*`), шрифты (`--font-sans`, `--font-serif`), радиусы
(`--radius-card`, `--radius-chip`) и тени (`--shadow-card`, `--shadow-lift`) заданы там.
Чтобы добавить свой цвет, допишите переменную `--color-<имя>-<оттенок>` в блок `@theme`.

### Заменить источник данных

Данные сайта берутся только из `data/materials.json`. Чтобы заменить источник (например, с Telegram
на другой мессенджер), достаточно переписать `scripts/collect.ts` и/или добавить адаптеры.
UI и страницы при этом не трогаем.

## 9. Советы по разработке

- Держите `data/materials.json` в репозитории — упрощает деплой на GitHub Pages
- Тестируйте сбор на 1–2 источниках перед расширением
- При отладке AI можно временно выставить `ai.enabled: false` в конфиге
- Коммитьте `.env.example`, но **никогда** `.env`
- Следите за лимитами OpenRouter при массовом сборе
- Фильтрация и категоризация работают и с русским, и с английским текстом
- Все внутренние ссылки и пути к картинкам — только через `withBase()`, иначе на
  GitHub Pages ломаются ссылки с префиксом `/intensiv-project`
- Весь интерфейс и комментарии в коде — на русском языке
